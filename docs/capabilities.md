# Capabilities

Each capability is implemented by real modules in `engine/src/`, exposed through both the CLI (`engine/src/cli.js`) and the MCP server (`engine/src/server.js`). All names below were verified against those two files. Capabilities compose; none replaces the host agent's execution role.

## 3. Controlled Multi-Agent Engineering

Plan and coordinate work across agents with project-scoped context, file ownership, evidence-required validation, and a workflow state machine that dispatches only with single-use approval.

**Modules (verified):** `agentOrchestrator.js`, `taskDecomposition.js`, `agentRegistry.js`, `agentCoordination.js`, `agentContext.js`, `agentConflicts.js`, `agentValidation.js`, `agentIntegration.js`, `agentWorkflowLearning.js`, `controlledWorkflow.js`, `workflowApproval.js`, `workflowStateMachine.js`, `workflowDispatcher.js`, `opencodeRunAdapter.js`, `workflowMonitor.js`, `workflowRecovery.js`, `workflowValidation.js`, `testExecution.js`, `workflowTemplates.js`.

**MCP tools (verified):** `agent_plan_create`, `agent_plan_status`, `agent_report`, `agent_resume`, `agent_selection_explain`, `agent_discover`, `agent_task_claim`, `agent_task_complete`, `agent_task_fail`, `agent_context_prepare`, `agent_conflicts`, `agent_result_validate`, `agent_integrate`, `workflow_templates`, `workflow_create`, `workflow_approve`, `workflow_approvals`, `workflow_dispatch`, `workflow_status`, `workflow_validate`, `workflow_recover`, `workflow_test`, `workflow_feedback`, `workflow_report`.

**Guarantees:** default `simulation` mode; `workflow-dispatch` defaults to `dry-run: true`; approval token is single-use and bound to project/plan/scope/mode/risk; replay and rebinding rejected; `process_ok` never sets `task_verified`; fixed-argument adapter with injectable spawn and no shell. Execution is handed to supported host-agent interfaces. **Real Harness-dispatched agent execution was not demonstrated in Phase 28.**
